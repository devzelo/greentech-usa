# Deployment — Vercel (frontend) + Render (backend)

The frontend calls the backend **directly** via an API base URL (`VITE_API_URL`), and the
backend serves the API + uploaded files with CORS enabled. Uploaded documents live on a
**persistent disk** on Render so they survive deploys.

```
  Browser ──HTTPS──▶ Vercel (static SPA)
     │
     └──HTTPS──▶ Render (Express API + /uploads on a persistent disk) ──▶ MongoDB Atlas
```

---

## 0. Prerequisites — MongoDB Atlas
- Atlas → **Network Access** → allow the backend to connect. Render doesn't give a single
  static outbound IP on Starter, so the simplest is **Allow access from anywhere** `0.0.0.0/0`
  (the connection is still protected by the DB user + password in `MONGO_URI`). For tighter
  security, use Render **static outbound IPs** (paid add-on) and allowlist those instead.
- Have your `MONGO_URI` ready (Atlas → Connect → Drivers).

---

## 1. Backend → Render
1. Push this repo to GitHub (already done).
2. Render → **New → Blueprint** → select the repo. It reads `render.yaml` and creates the
   `greentech-api` web service **with a 10 GB disk** mounted at `backend/uploads`.
   - (Or **New → Web Service** manually: Root Dir `backend`, Build `npm install --include=dev`,
     Start `npm start`, Health check `/api/health`, and add a Disk at
     `/opt/render/project/src/backend/uploads`.)
3. Set the env vars Render didn't generate:
   - `MONGO_URI` — your Atlas connection string
   - `FRONTEND_URL` — your Vercel URL, e.g. `https://greentech-usa.vercel.app`
   - `ALLOWED_ORIGINS` — same Vercel URL(s), comma-separated (add your custom domain too)
   - `JWT_SECRET` is auto-generated; `PORT=4000` and `NODE_VERSION=20` are preset.
4. Deploy. Note the service URL, e.g. `https://greentech-api.onrender.com`.
   Verify: open `https://greentech-api.onrender.com/api/health` → `{"status":"ok"}` (or 200).

> **Disk note:** the disk is on Starter+ ($7/mo). On the **free** tier there is no persistent
> disk, so every deploy/restart deletes all uploaded documents — don't use free for this app.

---

## 2. Frontend → Vercel
1. Vercel → **New Project** → import the same repo.
2. **Root Directory: `frontend`** (important — it's a monorepo). Framework preset **Vite**.
   Build `npm run build`, Output `dist` (also set in `frontend/vercel.json`).
3. Add an Environment Variable:
   - `VITE_API_URL` = your Render backend URL, e.g. `https://greentech-api.onrender.com`
     (no trailing slash).
4. Deploy. Note the URL, e.g. `https://greentech-usa.vercel.app`.

---

## 3. Wire the two together
- Back on **Render**, make sure `ALLOWED_ORIGINS` and `FRONTEND_URL` contain the **exact**
  Vercel URL (and any custom domain). Save → it redeploys.
- Reload the Vercel site, open DevTools → Network, log in: requests should go to
  `https://greentech-api.onrender.com/api/...` and succeed (no CORS errors).

---

## 4. First admin user
The DB starts empty. Create an admin via the Render **Shell** (service → Shell tab):
```bash
npm run create-user      # follow the prompts (name / email / password / role)
# or seed sample data:
npm run seed
```

---

## 5. Custom domains (optional)
- Vercel: add your domain to the project; point DNS as instructed.
- Render: add a custom domain to the service (e.g. `api.yourdomain.com`).
- Then update `VITE_API_URL` (Vercel) and `ALLOWED_ORIGINS` / `FRONTEND_URL` (Render) to the
  final domains and redeploy both.

---

## Environment variables at a glance
| Where   | Variable          | Example                                   |
|---------|-------------------|-------------------------------------------|
| Render  | `MONGO_URI`       | `mongodb+srv://user:pass@cluster/db`      |
| Render  | `JWT_SECRET`      | (auto-generated by Render)                |
| Render  | `FRONTEND_URL`    | `https://greentech-usa.vercel.app`        |
| Render  | `ALLOWED_ORIGINS` | `https://greentech-usa.vercel.app`        |
| Render  | `PORT`            | `4000`                                    |
| Vercel  | `VITE_API_URL`    | `https://greentech-api.onrender.com`      |

Optional SMTP on Render (for real password-reset/backup emails): `EMAIL_HOST`, `EMAIL_PORT`,
`EMAIL_USER`, `EMAIL_PASS` (Gmail: use an App Password).
